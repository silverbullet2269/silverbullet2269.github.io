## 概要

### 基本概念

下图为小红书中推荐系统的转化流程

![](\images\王树森推荐系统\img1.png)

图中的消费指标可以反映用户对于推荐是否满意：
- 点击率 = 点击次数 / 曝光率
- 点赞率 = 点赞次数 / 点击次数
- 收藏率 = 收藏次数 / 点击次数
- 转发率 = 转发次数 / 点击次数
- 阅读完成率 = 滑动到底次数 / 点击次数 * $f\text(笔记长度)$

对于阅读完成率来说，存在一个潜在问题：短笔记天然更容易获得高完成率，而长笔记即使质量很高，完成率也可能较低。所以我们就使用一个归一化函数 $f(\cdot)$ 将笔记长度归一化，乘该归一化长度可以一定程度上消除笔记长度带来的偏差。

上述消费指标都是一些短期指标，这些指标有意义，但并不是衡量推荐系统好坏的根本指标，这是因为如果只关注短期消费指标，那么给用户推荐的内容就会呈现同质化严重的现象，会导致用户迅速审美疲劳，从而降低用户粘性。所以短期消费指标不是最终的指标，最重要的指标是北极星指标：

- 用户规模：日活用户数(DAU)、月活用户数(MAU)
- 消费：人均使用推荐的时长、人均阅读笔记的数量
- 发布：发布渗透率、人均发布量

用户今天使用了小红书，那么就给小红书提供了一个 DAU；用户这个月使用了小红书，不论是登陆了一天还是30天，都给小红书提供了一个 MAU。用户规模与推荐系统的好坏是强相关的，推荐系统越好，用户规模越大。

### 推荐系统链路
推荐系统目标：从几亿物品中选取几十个物品推荐给用户。

通过下图链路，实现该筛选过程：

![](\images\王树森推荐系统\img3.png)

首先是召回，我们通过召回从数据库中取出一些笔记，在实践中通常有许多条召回通道，而召回通道包括有协同过滤、双塔模型、关注的作者等等。在小红书中，有几十条召回通道，每条召回通道取回几十到几百篇笔记，这些召回通道一共返回几千篇笔记，然后推荐系统会融合这些笔记，并进行去重和过滤的操作（这里过滤是指去掉用户不喜欢的作者、不喜欢的笔记）。

在召回之后，下一步是排序。通常将排序分为粗排和精排，粗排使用比较简单的模型快速对几千篇笔记进行打分，保留分数最高的几百篇笔记，精排是使用一个较大的神经网络对几百篇笔记打分。精排相对粗排使用的模型更大、特征更多，相对应的计算也会更复杂。结果会更准确。所以为了平衡计算量和准确度我们先粗排后再进行精排。

如下图所示，粗排和精排都是在神经网络中输入用户特征、物品特征和统计特征信息，然后经过神经网络训练，输出预测的点击率、点赞率、收藏率和转发率，再将这些指标进行融合就可以得到排序分数，这也是我们进行筛选和排序的依据。

![](\images\王树森推荐系统\img4.png)

在排序后，每篇笔记都有一个分数，表示用户对笔记的兴趣有多高。然后还需要再从几百篇笔记中进行随机抽样，抽取几十篇笔记然后利用规则将内容相似的笔记进行打散，并插入广告和运营物品，根据生态再调整排序。其中多样性抽样（如MMR、DPP）是最重要的。

### 分层实验

分层实验是为了解决“流量不够用”的问题。在一个公司中会有许多团队和部门，都需要做A/B测试，比如推荐系统（召回、粗排、精排、重排）团队、用户界面团队和广告团队。每个团队都需要做实验，那么可能需要同时做成千上百个实验，但将用户随机分为 10 组，1 组作为对照组，那么最多同时只能做 9 个实验，显然这无法达到需求。所以我们就需要做分层实验。下面具体介绍分层实验。

![](\images\王树森推荐系统\img7.png)

**分层实验的核心思想：将不同业务模块划分为不同实验层，让同一批用户在不同层中重复参与实验，从而提高流量利用率。**

需要记住两个原则：

- 同层互斥：同一层中，不同实验使用互不重叠的流量，避免实验策略相互冲突。
- 不同层正交：不同层独立随机分桶。

举个具体的例子，假设有 100 万用户，我们要同时做两个实验：

- 第一层（召回层）：策略 A（旧召回）和策略 B（新召回）。
- 第二层（UI 层）：策略 C（旧 UI）和策略 D（新 UI）。

每层都按照 50% : 50% 分配用户。

1. 错误方式：两层共用同一套分桶结果

    假设先把 100 万用户分为两个桶：

    | 用户桶 | 召回层 | UI 层 |
    |---|---|---|
    | 桶 1（50 万） | A | C |
    | 桶 2（50 万） | B | D |

    这样实际上只有两种组合：

    - 50 万用户使用 A+C
    - 50 万用户使用 B+D

    假如 B+D 的点击率更高，我们无法判断是新召回 B 有效，还是新 UI D 有效。

2. 正确方式：每一层都独立分桶

    召回层独立分桶，把 100 万用户随机分成两个桶：

    - 召回桶 1：50 万用户，使用策略 A
    - 召回桶 2：50 万用户，使用策略 B

    UI 层重新独立分桶，仍然使用全部 100 万用户，但通过另一套独立随机规则重新分桶：

    - UI 桶 1：50 万用户，使用策略 C
    - UI 桶 2：50 万用户，使用策略 D

    关键点：UI 层是重新对全部用户分桶，与召回层无关

    在这样的划分情况下，因为两层独立随机分桶，所以理论上形成四种组合：
    | 召回层 | UI 层 |
    |---|---|
    | A | C |
    | A | D |
    | B | C |
    | B | D |

    每种组合的概率为：$P(A\cap C)=P(A)\times P(C)=50\%\times50\%=25\%$。虽然同一用户同时参与召回实验和 UI 实验，但是由于两个实验独立随机分桶，所以我们可以分别估计它们的平均处理效果。

    假设四种组合的点击率如下：

    | 召回策略 | 旧 UI（C） | 新 UI（D） |
    |---|---|---|
    | 旧召回（A） | 10% | 12% |
    | 新召回（B） | 14% | 16% |

    那么计算计算召回层的效果，不管用户使用旧 UI 还是新 UI，只比较旧召回和新召回。旧召回平均点击率：$(10\%+12\%)/2=11\%$，新召回平均点击率：$(14\%+16\%)/2=15\%$。因此，新召回的平均提升为：$15\%-11\%=4\%$

    计算 UI 层的效果，不管用户使用旧召回还是新召回，只比较旧 UI 和新 UI。旧 UI 平均点击率：$(10\%+14\%)/2=12\%$，新 UI 平均点击率：$(12\%+16\%)/2=14\%$。因此，新 UI 的平均效果为：$14\%-12\%=2\%$

### Holdout 机制

Holdout机制解决的是长期效果评估的问题，比如说一家公司不停进行召回、粗排、精排和重排等实验，一段时间后，如果管理层询问这些所有层的优化累积起来，核心业务指标提升了多少，如果没有Holdout，我们无法评估这个问题，因为每个用户在A层为对照组，在B层也可能是对照组，所以所有用户都或多或少被实验影响，我们没有“未受干扰”的基准进行比较。所以Holdout机制就是提供这个基准。

![](\images\王树森推荐系统\img8.png)

Holdout机制的基本思想如下：
1. 取10%的用户作为Holdout桶，推荐系统使用剩余90%的用户做实验，两者互斥；
2. 考察10%Holdout桶与90%实验桶的差异（需归一化）作为整个部门的业务指标收益；
3. 每个考核周期结束之后，清除Holdout桶，让推全实验从90%用户扩大到100%用户；
4. 重新随机划分用户，得到Holdout桶和实验桶，开始下一轮考核周期；
5. 初始的新Holdout桶与实验桶的各种业务指标的差异接近0，随着召回、粗排、精排、重排实验上线和推全，差异会逐渐扩大。

### 实验推全和反转实验
实验推全：在Holdou机制基础上，观测到某个策略对某个桶有明显提升，关闭A/B测试，将策略推全到整个90%用户上。需要在召回层之前新建一个推全层，该层与其他层正交。

![](\images\王树森推荐系统\img9.png)

但实验推全还存在一个问题，有些指标（点击、交互）可以立刻收到薪策略的影响，短期内给出反馈。但有一些指标（留存）具有滞后性，短期内是无法给出反馈的，需要长期观测。但一方面我们希望早日推全新策略，以空出桶来供其他实验进行，但另一方面我们也不希望忽略这些滞后性的指标。那么我们就引入了反转实验。

反转实验：在实验推全的新层中设立一个旧策略的桶，长期观测实验指标。且holdout桶与反转桶也无关。在考核周期结束后，清除holdout桶，推全策略时，反转桶仍然不变保持旧策略，只有在反转实验结束后才会关闭反转桶，真正将新策略推全至100%的用户。

## 召回（Retrieval）

### ItemCF（基于物品的协同过滤）

ItemCF（Item-based Collaborative Filtering）的核心思想是：**用户的兴趣具有一定的连贯性，喜欢某个物品的用户，通常也会对与该物品相似的其他物品感兴趣。**

例如，用户 A 喜欢物品 $item_1$，而物品 $item_2$ 与 $item_1$ 的相似度较高，那么我们就可以推测用户 A 也可能喜欢物品 $item_2$。

那么，如何判断两个物品是否相似呢？

ItemCF 主要利用用户行为的相似性来衡量物品之间的关系。例如，喜欢物品 $item_1$ 的用户中，有 70% 也喜欢物品 $item_2$，说明两个物品具有较高的用户重合度，因此可能存在较强的关联性。

需要注意，ItemCF 衡量的是用户行为上的相似性，而不一定是物品内容或属性上的相似性。

ItemCF 主要分为三个步骤：

1. 计算用户兴趣分数：根据用户对历史物品的交互行为（如点击、点赞、收藏、购买等），量化用户对物品的喜欢程度，记为 $like(user,item_j)$。

2. 计算物品相似度：根据**所有用户**的历史行为，计算候选物品 $i$ 与用户历史交互物品 $j$ 之间的相似度，记为 $sim(item_j,item_i)$。

3. 预测用户兴趣：将目标用户对历史物品的喜欢程度与物品相似度相乘，再进行加权求和，得到用户对候选物品的兴趣预测分数：
$
\sum{like(user,item_j)\cdot sim(item_j,item_i)}
$

![](\images\王树森推荐系统\img12.png)

计算物品相似度的基本思路是：两个物品的用户群体重合度越高，它们的相似度通常也越高。

假设：

- $W_1$：喜欢物品 $i_1$ 的用户集合。
- $W_2$：喜欢物品 $i_2$ 的用户集合。
- $V=W_1\cap W_2$：同时喜欢两个物品的用户集合。

可以定义物品相似度为：
$
sim(i_1,i_2)=\frac{|V|}{\sqrt{|W_1|\cdot|W_2|}}
$

该公式通过共同用户数量衡量两个物品的相似程度，同时利用分母进行归一化，避免仅因为某个物品用户数量较多，就认为它与其他物品高度相似。
但是，这种方法只考虑了用户是否喜欢某个物品，没有考虑用户对物品的喜欢程度。例如，物品 A 和 B 拥有相同的用户群体，但这些用户可能非常喜欢 A，却只是轻微喜欢 B。仅根据用户是否交互，无法体现这种喜好强度的差异。

为了更准确地衡量物品之间的关系，可以进一步引入用户对物品的兴趣分数 $like(u,i)$，使用余弦相似度：
$$
sim(i_1,i_2)=
\frac{\sum_{u\in V}like(u,i_1)\cdot like(u,i_2)}
{\sqrt{\sum_{u\in W_1}like^2(u,i_1)}
\cdot\sqrt{\sum_{u\in W_2}like^2(u,i_2)}}
$$

其本质其实就是常见的余弦相似度表达式。我们将 $W_1$ 集合每个元素对 $i_1$ 的喜欢程度看作一个向量，$W_2$ 集合每个元素对 $i_2$ 的喜欢程度看作一个向量。在分子位置，当不是同时喜欢两个物品的用户相乘时，结果为 0 直接忽略，即为公式中展示的 $V$ 集合的用户对两个物品的喜欢程度相乘。

![](\images\王树森推荐系统\img13.jpg)

为什么计算相似度和预测兴趣时都需要 like？虽然两个阶段都使用了 $like$，但它们的作用并不相同。

- 计算物品相似度时：利用**所有用户**对两个物品的兴趣分数，判断两个物品的用户喜好模式是否一致，解决的是“两个物品有多相似”的问题。
- 预测用户兴趣时：利用**当前目标用户**对历史物品的兴趣分数，衡量每个历史物品对候选物品推荐结果的贡献，解决的是“目标用户有多可能喜欢候选物品”的问题。

例如，用户 A 非常喜欢历史物品 $i_1$，但只对历史物品 $i_2$ 有轻微兴趣。当候选物品同时与 $i_1$、$i_2$ 相似时，显然应当让 $i_1$ 对预测结果产生更大的影响，因此需要使用 $like(u,j)$ 进行加权。

下面介绍 ItemCF 召回的完整流程：

1. 离线计算
    - 建立 User → Item 索引：记录用户最近点击、交互过的物品，并计算兴趣分数。根据索引可以得到用户近期感兴趣的物品列表 `{用户ID: [(物品ID, 兴趣分数)]}`。
    - 建立 Item → Item 索引：计算物品之间的相似度。对于每个物品，保存与它最相似的 Top-K 个物品 `{物品ID: [(相似物品ID, 相似度)]}`。

2. 在线召回
    - 根据用户 ID，查询 User → Item 索引，获取用户最近感兴趣的 N 个物品（Last-N）。
    - 对于 Last-N 中的每个物品，查询 Item → Item 索引，获取 Top-K 个相似物品。
    - 合并候选物品，最多得到 N × K 条候选关系。
    - 根据用户历史兴趣分数和物品相似度，计算候选物品的推荐分数。
    - 返回得分最高的 100 个物品。

线上召回时索引可以避免暴力枚举所有物品。虽然离线计算量大，但是有效减少了线上计算量。

### Swing 召回通道
Swing 召回算法可以看作 ItemCF 的一种改进，二者的主要区别在于**物品相似度的计算方式**。

对于 ItemCF 算法，通常通过用户与物品的交互行为计算物品之间的相似度。我们认为两个物品的受众重合度越高，那么这两个物品的相似度就越高。

但这种方法存在一个问题：**ItemCF 没有显式考虑共同用户之间的行为相关性，因此可能产生虚假的物品关联。** 例如，“护肤品打折”和“字节裁员”是两个内容上毫不相关的帖子，正常情况下，它们不应该具有很高的相似度。但是，如果这两个帖子被分享到同一个微信群，群内大量用户都点击了这两个帖子，那么它们就会拥有大量共同交互用户。ItemCF 算法可能会计算出较高的相似度，从而错误地认为两个帖子具有较强的关联性，与事实相悖。

为缓解这一问题，引入了 Swing 算法。

Swing 的核心思想是：如果大量用户同时喜欢两个物品，且这些用户之间的相关性低，那么这两个物品一定是强关联。因此，Swing 在计算物品相似度时，不仅考虑共同交互的用户，还会考虑这些用户之间的历史交互重合程度。

![](\images\王树森推荐系统\img14.png)

Swing 算法首先定义两个用户之间的重合度：

$$
\operatorname{overlap}(u_1,u_2)
=
|\mathcal J_1\cap\mathcal J_2|
$$

其中，$\mathcal J_1$ 和 $\mathcal J_2$ 分别表示用户 $u_1$ 和 $u_2$ 喜欢的物品集合。两个用户共同喜欢的物品越多，说明他们的历史交互行为越相似。

接下来，定义喜欢物品 $i_1$ 和 $i_2$ 的用户集合分别为 $\mathcal W_1$ 和 $\mathcal W_2$，两个物品的共同用户集合为：

$$
\mathcal V=\mathcal W_1\cap\mathcal W_2
$$

Swing 根据这些共同用户之间的重合度，计算两个物品的相似度：

$$
\operatorname{sim}(i_1,i_2)
=
\sum_{u_1\in\mathcal V}
\sum_{u_2\in\mathcal V}
\frac{1}{\alpha+\operatorname{overlap}(u_1,u_2)}
$$

其中，$\alpha$ 是平滑参数，用于防止分母为零，并调节用户重合度对相似度贡献的影响。

从公式可以看出，两个用户的历史交互重合度越高，他们对物品相似度的贡献就越小；反之，贡献越大。

其背后的直觉是：如果两个用户的历史行为高度相似，那么他们可能受到相同兴趣圈子或外部因素的影响，因此共同喜欢两个物品所提供的额外证据较弱。而如果两个用户平时的兴趣差异较大，却同时喜欢两个物品，那么这一共同交互更能支持两个物品存在关联。

因此，Swing 通过降低高度相似用户之间的贡献，在一定程度上缓解了 ItemCF 容易受到用户小圈子集中交互影响的问题。

### 基于用户的协同过滤 (UserCF)
UserCF 与 ItemCF 类似，ItemCF 是通过相似物品来推荐，而 UserCF 是通过相似用户来推荐.UserCF的核心是：如果 $user_1$ 和 $user_2$ 相似，那么 $user_2$ 喜欢的物品 A，我们认为$user_1$ 很大可能也喜欢。

同 ItemCF，在 UserCF 中，也可以通过相似的用户和这些用户对于物品 A 的兴趣分数，得到 user 对一个新物品 A 的兴趣分数，$\sum{like(user_i,user_j)\cdot sim(user_j,item)}$。

![](\images\王树森推荐系统\img15.png)

UserCF 根据用户之间的兴趣相似度进行推荐。当两个用户喜欢的物品重合程度越高时，通常认为他们的兴趣越相似。所以假设：

- $\mathcal J_1$：用户 $u_1$ 喜欢的物品集合。
- $\mathcal J_2$：用户 $u_2$ 喜欢的物品集合。
- $I=\mathcal J_1\cap \mathcal J_2$：两个用户同时喜欢的物品集合。

可以定义两个用户的相似度为：
$
sim(u_1,u_2)=\frac{|I|}{\sqrt{|\mathcal J_1|\cdot|\mathcal J_2|}}
$

但是，该公式将所有共同交互物品视为同等重要，没有考虑物品热门程度的影响。例如，《哈利波特》拥有大量受众，即使两个用户的兴趣差异很大，他们也可能同时喜欢《哈利波特》。因此，共同喜欢热门物品并不能充分说明两个用户的个性化兴趣相似。

为了解决这一问题，可以引入热门物品惩罚，对每个共同交互物品赋予 $\frac{1}{\log(1+n_l)}$ 的权重，其中 $n_l$ 表示喜欢物品 $l$ 的用户数量。物品越热门，其贡献权重越低；物品越冷门，其贡献权重相对越高。

两个用户的相似度为：
$$
sim(u_1,u_2)=\frac{\sum_{l\in I}\frac{1}{\log(1+n_l)}}{\sqrt{|\mathcal J_1|\cdot|\mathcal J_2|}}
$$

这样一来，UserCF 就能降低热门物品对用户相似度的影响，使共同喜欢的、具有较强区分度的物品在相似度计算中发挥更大的作用。

下面介绍 UserCF 召回的完整流程：

1. 离线计算
    - 建立 User → Item 索引：记录用户最近点击、交互过的物品，并计算兴趣分数。根据索引可以得到用户近期感兴趣的物品列表 `{用户ID: [(物品ID, 兴趣分数)]}`。
    - 建立 User → User 索引：计算用户之间的相似度。对于每个用户，保存与她最相似的 Top-K 个物品 `{用户ID: [(相似用户ID, 相似度)]}`。

2. 在线召回
    - 根据用户 ID，查询 User → User 索引，获取与目标用户最相似的 Top-K 个用户。
    - 对于这 K 个相似用户，分别查询 User → Item 索引，获取每个相似用户最近感兴趣的 N 个物品（Last-N）。
    - 合并候选物品，最多得到 N × K 条候选关系。由于不同用户可能交互过同一物品，因此需要对候选物品进行去重。
    - 根据目标用户与相似用户之间的相似度，以及相似用户对候选物品的兴趣分数，计算目标用户对候选物品的预测兴趣分数。
    - 返回得分最高的 100 个物品。

### 离散特征处理

推荐系统中，用户 ID、物品 ID、类别 ID 等都属于离散特征。由于这些 ID 只是编号，本身不具有数值意义，因此不能直接将其作为连续数值输入模型，需要先进行特征编码。

常见的离散特征编码方式包括 One-Hot 和 Embedding。

#### One-Hot 编码

One-Hot 将每个类别映射为一个独立的高维稀疏向量。例如，假设有 3 个物品：

- 物品 A：`[1, 0, 0]`
- 物品 B：`[0, 1, 0]`
- 物品 C：`[0, 0, 1]`

One-Hot 存在两个主要问题：

1. 维度过高：如果有 100 万个物品，那么 One-Hot 向量就有 100 万维。虽然可以使用稀疏存储，但直接进行稠密计算的成本较高。
2. 无法直接表达类别之间的相似性：不同物品的 One-Hot 向量相互正交，无法体现物品之间的潜在关联。

因此，在大规模推荐系统中，通常使用 Embedding 来表示高基数离散特征。

#### Embedding 编码

Embedding 的核心思想是将离散 ID 映射为可训练的低维稠密向量。

例如，将物品 ID 映射为 4 维向量：

```text
物品 A → [0.8, 0.2, 0.5, 0.1]
物品 B → [0.7, 0.3, 0.4, 0.2]
物品 C → [0.1, 0.9, 0.2, 0.8]
```

Embedding 的参数以矩阵形式存储：

$$
E\in\mathbb R^{N\times d}
$$

其中：

- $N$：离散特征的类别数量。
- $d$：Embedding 向量维度。
- $E$：Embedding 参数矩阵。

因此，参数总数为：$N\times d$

例如，有 100 万个物品，每个物品使用 32 维 Embedding，那么参数总数为：$10^6\times32=3200万$

Embedding 的本质是通过 ID 查询参数矩阵中的对应向量，并在模型训练过程中不断更新向量参数。如果训练效果较好，Embedding 可以学习到用户或物品的潜在特征。如下图所示，位于第一象限的物品都为动画片，位于第二象限的物品为漫威影片。

![](\images\王树森推荐系统\img16.png)

需要注意，Embedding 各维度通常不具有明确的人工语义，物品之间的距离是否能够反映兴趣相似性取决于模型的训练目标。

TensorFlow、PyTorch 等深度学习框架都提供了 Embedding 层。

### 矩阵补全

（这种方法已不再使用）

矩阵补全（Matrix Completion）是一种基于用户和物品 Embedding 的推荐方法。其核心思想是：为每个用户和物品分配一个可训练的 Embedding 向量，通过已有的交互数据不断优化向量，使两者的内积接近真实兴趣分数，再利用训练好的向量预测用户对未知物品的兴趣。

假设存在用户-物品兴趣矩阵：

| 用户 / 物品 | A | B | C | D |
|---|---|---|---|---|
| U1 | 4 | 3 | ? | ? |
| U2 | ? | 2 | 4 | ? |
| U3 | 3 | ? | ? | 4 |

其中，已知数值表示用户对物品的兴趣分数，`?` 表示兴趣未知。矩阵补全的目标就是预测这些未知位置的分数，从而找到用户可能感兴趣的物品。

#### 模型结构

模型输入用户 ID 和物品 ID，分别通过 Embedding 层映射为向量：

$$
u\longrightarrow a_u,\qquad i\longrightarrow b_i
$$

其中，$a_u,b_i\in\mathbb R^d$ 分别表示用户和物品的 Embedding 向量。

通过向量内积预测用户对物品的兴趣分数：

$$
\hat y_{ui}=\langle a_u,b_i\rangle
=\sum_{k=1}^{d}a_{u,k}b_{i,k}
$$

例如：

$$
a_u=[0.8,0.3,0.5],\qquad b_i=[0.7,0.2,0.9]
$$

则预测兴趣分数为：

$$
\hat y_{ui}=0.8\times0.7+0.3\times0.2+0.5\times0.9=1.07
$$

#### 模型训练

首先构建用户-物品交互数据集：

$$
\Omega=\{(u,i,y)\}
$$

其中，$u$ 为用户 ID，$i$ 为物品 ID，$y$ 为真实兴趣分数。其中兴趣分数是系统记录的，比如：曝光但是没有点击记为 0 分，点击、点赞、收藏、转发各算 1 分。具体的兴趣分数定义取决于业务场景。

假设系统中有 $m$ 个用户、$n$ 个物品，Embedding 维度为 $d$，则：

$$
A\in\mathbb R^{m\times d},\qquad
B\in\mathbb R^{n\times d}
$$
其中，$A$ 和 $B$ 分别为用户和物品的 Embedding 参数矩阵。

模型的训练目标是使预测分数尽可能接近真实分数，因此可以采用平方误差损失：

$$
\min_{A,B}
\sum_{(u,i,y)\in\Omega}
\left(y-\langle a_u,b_i\rangle\right)^2
$$

训练过程中，通过不断调整 Embedding 参数，减小预测值与真实值之间的误差。

完整的兴趣预测矩阵可以表示为：

$$
\hat R=AB^\top
$$

![](\images\王树森推荐系统\img17.png)

模型通过已知的交互数据学习参数，再预测矩阵中未知位置的兴趣分数，从而实现矩阵补全。

#### 矩阵补全的局限性

虽然矩阵补全模型结构简单，但在实际推荐系统中存在一些问题。

（1）仅使用 ID Embedding，缺少其他特征

模型只使用用户 ID 和物品 ID，没有直接利用用户属性、物品类别、上下文等信息。此外，新用户和新物品缺少历史交互数据，难以学习可靠的 Embedding，容易出现冷启动问题。

（2）负样本选取问题

矩阵补充将曝光之后，没有点击、交互的样本设置为负样本，但这样是错误的，具体该如何选取负样本在后面介绍。

（3）内积受到向量模长的影响

矩阵补全使用向量内积预测兴趣分数：

$$
\langle a_u,b_i\rangle
=\|a_u\|\cdot\|b_i\|\cdot\cos\theta
$$

内积不仅受到向量夹角的影响，还受到向量模长的影响。

如果希望重点衡量向量方向上的相似程度，可以使用余弦相似度：

$$
\operatorname{sim}(a_u,b_i)
=
\frac{\langle a_u,b_i\rangle}
{\|a_u\|\cdot\|b_i\|}
$$

但内积并不一定比余弦相似度差，具体选择取决于模型设计和业务目标。

（4）平方损失不一定适合点击预测

矩阵补全通常采用平方误差损失（MSE），适合连续兴趣分数或评分预测。

而点击预测属于二分类任务，通常更适合使用二元交叉熵损失（BCE）：

$$
L_{\mathrm{BCE}}
=-\left[y\log p+(1-y)\log(1-p)\right]
$$

其中，$p$ 为预测点击概率。

### 线上服务
矩矩阵补充模型训练好后可作为召回通道，所以我们需要将模型存储好。在矩阵补充模型中需要保存用户和物品的 Embedding 参数矩阵：$A\in\mathbb R^{m\times d}, B\in\mathbb R^{n\times d}$。

用户矩阵 $A$ 可以存储到 Key-Value 数据库中：Key：用户 ID、Value：对应的用户 Embedding 向量 $a_u$。线上只需要提供用户 ID，就能快速查询该用户的向量。

物品矩阵 $B$ 不能仅依赖普通 Key-Value 查询，因为召回时并不知道应该查找哪些物品 ID。我们的目标是：给定用户向量 $a_u$，快速找到与其内积最大的 K 个物品向量。如果物品矩阵 $B$ 使用简单的 Key-Value 查询，那我们线上服务时需要遍历所有物品，逐一计算：$\langle a_u,b_i\rangle$，当物品数量非常大时，计算成本较高，因此需要通过近似最近邻搜索（ANN）加速。

ANN（Approximate Nearest Neighbor）的核心思想是：提前将物品 Embedding 划分为多个区域并建立索引，线上只搜索与用户向量最匹配的部分区域，避免遍历所有物品。

（1）离线建立向量索引

首先，获取所有物品的 Embedding 向量，并将向量空间划分为 $N$ 个区域（图中每个扇形区域），每个区域包含一部分物品。然后为每个区域选取一个代表向量（例如聚类中心）。

（2）线上进行向量召回

当用户发起推荐请求时，首先根据用户 ID 查询 Key-Value 数据库，获取用户的 Embedding 向量 $a_u$。然后计算用户向量与各区域代表向量的相似度，找到最相似的一个或多个区域。接下来，只需遍历选中区域内的物品，计算用户向量与这些物品向量的内积，得到预测兴趣分数。最后，根据预测兴趣分数对候选物品进行排序，返回得分最高的 Top-K 个物品作为召回结果。这样就避免了遍历所有物品，提高了线上召回效率。

![](\images\王树森推荐系统\img18.png)

在工业界中，Milvus、Faiss、HnswLib等向量数据库都支持近似最近邻查找。

### 双塔模型

双塔模型是在矩阵补全模型的基础上发展而来的深度学习推荐模型。与矩阵补全主要使用用户 ID 和物品 ID 不同，双塔模型还引入用户和物品的其他特征，通过两个独立的神经网络分别生成用户和物品的 Embedding 向量，再计算向量相似度预测用户兴趣。

例如，用户特征可以包括用户 ID、所在城市、年龄、历史行为等；物品特征可以包括物品 ID、类别、标签、文本内容等。

![](\images\王树森推荐系统\img19.png)

![](\images\王树森推荐系统\img24.png)

双塔模型由用户塔（User Tower）和物品塔（Item Tower）组成：

$$
a_u=f_\theta(x_u),\qquad b_i=g_\phi(x_i)
$$

其中：

- $x_u$、$x_i$ 分别表示用户和物品的输入特征。
- $f_\theta$、$g_\phi$ 分别表示用户塔和物品塔的神经网络。
- $a_u$、$b_i$ 分别为生成的用户和物品 Embedding 向量。

模型通过两个向量的相似度衡量用户对物品的兴趣，例如使用余弦相似度：

$$
s(u,i)=\cos(a_u,b_i)
=\frac{\langle a_u,b_i\rangle}
{\|a_u\|\cdot\|b_i\|}
$$

双塔模型采用**后期融合**：先通过神经网络分别生成用户和物品向量，再计算二者的相似度。这种结构适合召回阶段，因为物品向量可以提前离线计算并建立 ANN 索引，线上只需要计算用户向量，就能快速检索相似物品。

相比之下，**前期融合**先结合用户和物品特征，再通过神经网络预测兴趣分数。这种结构允许模型学习更加复杂的用户-物品交互关系，但每个候选物品通常都需要单独进行模型推理。因此它更适合候选量已经缩小之后的粗排、精排。

![](\images\王树森推荐系统\img20.png)

需要注意，双塔模型也可以使用内积作为匹配分数，并不局限于余弦相似度。

双塔模型常见的训练方式包括 Pointwise、Pairwise 和 Listwise，三者主要区别在于正负样本的组织方式和优化目标。

（1）Pointwise

Pointwise 将每个用户-物品样本独立看作一个二分类问题，鼓励用户与正样本的余弦相似度 cos(a, b) 接近 +1，鼓励用户与负样本的余弦相似度 cos(a, b) 接近 -1，控制正负样本的数量为 1:2 或者 1:3 （经验值）。

（2）Pairwise

Pairwise 每次使用一个正样本和一个负样本，得到用户对这组正、负样本的余弦相似度 $\cos(a_u,b^+), \cos(a_u,b^-)$。训练时我们希望用户与正样本的相似度高于负样本，$\cos(a_u,b^+) > \cos(a_u,b^-)$，所以训练目标为：

$$
\cos(a_u,b^+) - \cos(a_u,b^-)\ge m
$$

其中，$m$ 为间隔参数，用于要求正负样本之间保持一定的分数差距。

![](\images\王树森推荐系统\img21.png)

常见的损失函数有两种：

Triplet Hinge Loss（间隔损失）

$$
L=\max\left(0,\cos(a,b^-)+m-\cos(a,b^+)\right)
$$

其中 $m$ 是间隔参数，要求正样本相似度至少比负样本高 $m$。如果满足这一条件，损失为 0；否则产生损失，推动模型拉大正负样本的分数差距。

Triplet Logistic Loss（逻辑损失）

$$
L=\log\left(1+\exp\left[\sigma\left(\cos(a,b^-)-\cos(a,b^+)\right)\right]\right)
$$

其中 $\sigma>0$ 为缩放系数。正样本相似度越高、负样本相似度越低，损失就越小。

两者的主要区别在于：Hinge Loss 要求正负样本的分数差达到指定间隔，达到后损失变为 0；Logistic Loss 则采用平滑函数，持续推动正样本分数高于负样本。

（3）Listwise

Listwise 每次使用一个正样本和多个负样本组成候选列表，通过 Softmax 将用户与各物品的余弦相似度转换为相对概率，再使用交叉熵损失训练模型。

首先计算用户向量 $a$ 与正负样本向量的余弦相似度：

$$
z^+=\cos(a,b^+),\qquad z_j^-=\cos(a,b^-)
$$

然后通过 Softmax 计算正样本在候选列表中的相对概率：

$$
s^+=
\frac{\exp(z^+)}
{\exp(z^+)+\sum_{j=1}^{n}\exp(z_j^-)}
$$

其中，正样本标签为 1，负样本标签为 0，交叉熵损失函数为：
$$
\begin{aligned}
L_{\mathrm{listwise}}
&=-\sum_{i=0}^{n}y^i\log s_i \\
&=-(1\cdot\log s^++0\cdot\log s_1^-+\cdots)\\
&=-\log s^+
\end{aligned}
$$

最小化交叉熵函数，让正样本的 Softmax 概率尽可能接近 1，从而提高正样本相对于所有负样本的匹配分数。

![](\images\王树森推荐系统\img22.png)

三种方法的核心区别可以概括为：

| 训练方式 | 样本组织 | 优化目标 |
|---|---|---|
| Pointwise | 单个正样本或负样本 | 预测样本标签 |
| Pairwise | 一个正样本 + 一个负样本 | 正样本得分高于负样本 |
| Listwise | 一个正样本 + 多个负样本（常见形式） | 正样本在候选列表中排名靠前 |

综上所述，Pointwise、Pairwise 和 Listwise 三种训练方法的核心目标都是提高用户与正样本的匹配分数，降低用户与负样本的相对匹配分数，使模型能够区分用户感兴趣和不感兴趣的物品。

那么我们该如何选择正负样本呢？

（1）正样本

通常将用户曝光后产生点击、购买等正向行为的用户-物品交互作为正样本。

但由于 28 法则，少部分的热门物品通常拥有更多的曝光机会，因此更容易获得点击，在训练集中占据更高的比例。模型通过这些数据进行训练后，会更加倾向于推荐热门物品，使热门物品获得更多曝光和点击。而冷门物品由于曝光较少，积累的交互数据不足，即使符合用户兴趣，也难以被模型充分学习和推荐。

这样就形成了一个不断强化的反馈循环：热门物品获得更多曝光 → 产生更多点击 → 在训练集中占比更高 → 模型更倾向于推荐热门物品 → 获得更多曝光。最终导致热门物品更热、冷门物品更冷。

常见解决方法包括：

- 过采样冷门物品：增加冷门正样本被选中的概率。
- 降采样热门物品：降低热门正样本的采样频率，抛弃概率与热门物品的点击次数正相关。

这样可以适当缓解热门物品占比过高的问题，提高训练数据的多样性。

（2）负样本采样

负样本即为用户不感兴趣的物品，也可以理解为是在推荐系统链路每一步中被淘汰的物品。我们可以将负样本分为简单负样本和困难负样本。

简单负样本：通常来自召回阶段未被选中的物品。这类物品大概率是用户不感兴趣的物品，模型比较容易将其与正样本区分开。

困难负样本：通常来自已经通过召回、但在粗排或精排阶段被淘汰的物品。这类物品是用户具有一定兴趣，但不是最感兴趣的样本，与正样本较为相似，因此模型更难区分。

需要注意，最终曝光但未被点击的物品不可以作为负样本，因为这些物品已经是筛选出来的用户感兴趣的物品，未被点击可能是其他因素影响。

接下来介绍简单负样本的采样方法

（1）全体物品采样

首先介绍从全体物品中抽取简单负样本。由于物品库规模远大于每次召回的物品数量（几亿个物品中只有几千个物品被召回），可以近似认为随机抽取的物品大部分没有被当前用户召回，因此将其作为简单负样本候选。

但如果采用均匀采样，由于物品库中冷门物品数量远多于热门物品，采样得到的负样本可能主要由冷门物品组成。模型会频繁降低这些冷门物品与用户的匹配分数，同样会导致热门物品更热、冷门物品更冷。

为缓解这一问题，采用非均匀采样，相对降低冷门物品的负采样率、提高热门物品的负采样概率，抽样概率正比于点击次数的 0.75 次方，其中 $0.75$ 是经验参数，并非固定要求。

（2）Batch 内负样本

在双塔模型的 Batch 内负采样方法中，通常先从用户历史点击日志中构建正样本数据集，再从中取出一批正样本组成 Batch。假设一个 Batch 包含 $n$ 条点击正样本：

$$
\mathcal B=\{(u_1,i_1),(u_2,i_2),\ldots,(u_n,i_n)\}
$$

对于用户 $u_1$，其点击的物品 $i_1$ 是正样本，而 Batch 中其他用户点击的物品 $i_2,\ldots,i_n$ 则被当作负样本。其他用户同理。

因此，在每条正样本对应不同物品的情况下，一个 Batch 最多可以构建 $n(n-1)$ 条负样本关系。

![](\images\王树森推荐系统\img23.png)

Batch 内负采样的优势在于无需额外从全量物品库中抽取负样本，直接复用当前 Batch 中的物品向量，能够提高训练效率。

但这种方法存在热门物品采样偏差。由于 Batch 来自用户点击日志，热门物品的点击次数越多，在训练数据中出现的频率就越高，也就越容易进入 Batch，成为其他用户的负样本。因此，Batch 内负样本的采样频率通常近似与物品点击次数成正比，与我们希望的点击次数的 $0.75$ 次方不一致。这可能导致热门物品被过度当作负样本，受到过多负向训练信号，从而造成偏差。

为缓解这一问题，可以采用 LogQ Correction（采样概率纠偏），在训练时将用户对物品 i 的兴趣公式 $\cos (a, b_i)$ 修改为 $\cos (a, b_i)-\log q_i$，$q_i$ 表示物品的采样概率。这种修正只用于训练阶段，线上召回时仍使用原始匹配分数。

通过考虑物品的采样频率，可以缓解非均匀采样导致的训练偏差。

在实际训练中，我们常常使用混合负样本，比如50%为简单负样本，50%为困难负样本。

接下来介绍双塔模型的线上召回和更新。

在训练好双塔模型的两个塔后，我们先使用物品塔提取物品特征，离线存储物品向量。对于几亿个物品，用物品塔计算每个物品的特征向量 b，把 `<物品向量，物品ID>` 存入向量数据库，以便加速最近邻查找。

然后进行线上召回，查找用户最感兴趣的 k 个物品。首先根据给定的用户 ID 和画像，使用用户塔线上计算用户向量 a，然后把 a 作为 query，调用向量数据库做最近邻查找，返回余弦相似度最大的 k 个物品，作为召回结果。

由于用户的兴趣变化是动态变化的，所以我们选择线上实时计算用户向量。而物品的特征相对稳定，且物品的数量过于庞大，所以我们选择线上召回之前，离线存储物品向量。

在实践中，需要对模型不断进行更新。更新也分为“全量更新”和“增量更新”。

全量更新较为简单，每天凌晨（一天结束时），在原先模型参数的基础上，使用最新一天的数据训练 1 epoch，得到新的用户塔神经网络和物品向量，供线上召回使用。全量更新对数据流、系统的要求较低。

而增量更新相对复杂一些。因为增量更新是实时进行更新，以确保能够与用户的兴趣完全契合，比如用户早上刷小红书产生了新的兴趣点，那么小红书就要通过增量更新实时更新，让用户在中午或者更早时候就可以刷到与新的兴趣点相关的内容。增量更新需要实时收集线上数据，做流式处理，生成TFRecord文件，对模型做online learning，增量更新用户塔的 ID Embedding 参数，注意不对神经网络其它部分（全连接层）的参数进行更新。然后发布 ID Embedding 参数，供用户塔线上计算用户向量。

### 双塔模型 + 自监督学习

传统双塔模型主要通过用户点击数据学习用户和物品的 Embedding，但推荐系统存在严重的头部效应：

- 热门物品：点击次数多，参与模型训练的机会多，因此 Embedding 学习得较充分。
- 长尾物品：点击次数少，参与模型训练的机会少，因此 Embedding 学习得不充分。

为缓解这一问题，可以引入自监督学习，利用物品自身的特征构造训练任务，使缺少点击数据的长尾物品也能参与训练，从而改善其向量表示。

核心思想是：对同一个物品进行两次不同的特征变换，同一物品通过变换得到的特征向量仍有高相似度，而不同物品之间的特征向量具有低相似度。

对于物品 $i$，通过两次特征变换生成两个不同的特征视图 $i'$ 和 $i''$，分别输入共享参数的物品塔：

$$
b_i'=g_\phi(i'),\qquad b_i''=g_\phi(i'')
$$

由于两个视图来自同一个物品，因此希望它们的向量相似度较高：

$$
\cos(b_i',b_i'')\uparrow
$$

而对于不同物品 $i$ 和 $j$，希望它们的向量能够被区分：

$$
\cos(b_i',b_j')\downarrow,\qquad \cos(b_i',b_j'')\downarrow
$$

![](\images\王树森推荐系统\img27.png)

假设推荐系统中有一条介绍佳能相机的摄影教程视频，其特征如下：

| 特征字段 | 原始值 |
|---|---|
| 物品 ID | V1001 |
| 类目 | 数码、摄影 |
| 关键词 | 佳能、相机、摄影教程 |
| 城市 | 上海 |
| 品牌 | 佳能 |
| 价格 | 5000～10000 元 |

接下来以这个物品为例，介绍四种特征增强方法。

（1）Random Mask：随机遮盖特征

随机选择一个离散特征字段，将整个字段的取值替换为默认值（`default`）。

例如，随机遮盖“类目”字段：

| 特征字段 | 原始物品 | 变换后 |
|---|---|---|
| 物品 ID | V1001 | V1001 |
| 类目 | 数码、摄影 | **default** |
| 关键词 | 佳能、相机、摄影教程 |  佳能、相机、摄影教程 |
| 城市 | 上海 | 上海 |
| 品牌 | 佳能 | 佳能 |
| 价格 | 5000～10000 元 | 5000～10000 元 |

（2）Dropout：随机丢弃部分特征值

Dropout 主要针对**多值离散特征**。与 Random Mask 不同，它不是遮盖整个字段，而是随机丢弃其中部分取值。

例如，对“关键词”字段进行 Dropout，随机丢弃部分关键词：

| 特征字段 | 原始物品 | 变换后 |
|---|---|---|
| 物品 ID | V1001 | V1001 |
| 类目 | 数码、摄影 | 数码、摄影 |
| 关键词 | 佳能、相机、摄影教程 | **佳能、摄影教程** |
| 城市 | 上海 | 上海 |
| 品牌 | 佳能 | 佳能 |
| 价格 | 5000～10000 元 | 5000～10000 元 |

这里随机删除了“相机”，但保留了其他关键词。

（3）Complementary：互补特征

将同一个物品的特征字段随机划分为两组，分别保留其中一组，并遮盖另一组，从而形成两个互补的特征视图。

例如，将六个特征字段分为：

$$
G_1=\{\text{ID、关键词、品牌}\}
$$

$$
G_2=\{\text{类目、城市、价格}\}
$$

得到两个视图：

| 特征字段 | 视图 1 | 视图 2 |
|---|---|---|
| 物品 ID | V1001 | default |
| 类目 | default | 数码、摄影 |
| 关键词 | 佳能、相机、摄影教程 | default |
| 城市 | default | 上海 |
| 品牌 | 佳能 | default |
| 价格 | default | 5000～10000 元 |

将两个视图分别输入共享参数的物品塔：

$$
b_i'=g_\phi(G_1),\qquad b_i''=g_\phi(G_2)
$$

虽然两个视图保留的特征不同，但它们都来源于同一个原始物品，因此可以构造正样本对：

$$
(b_i',b_i'')
$$

通过对比学习，鼓励：

$$
\cos(b_i',b_i'')\uparrow
$$

需要注意，两个视图并不是因为特征本身相似才被当作正样本，而是因为它们来自同一个物品。如果某个视图包含的信息太少，强行使两个向量相似也可能影响模型的区分能力。

（4）Mask 一组关联的特征

某些特征字段之间有较强的关联，遮住一个特征并不会损失太多的信息，模型可以从其他强关联特征中学到遮住的特征，例如：

- 类目为“摄影”的物品，其关键词经常包含“相机”。
- 品牌为“佳能”的物品，其关键词可能包含“佳能”。

如果只遮盖“类目”，模型仍可能通过“关键词”推断出物品的类目信息。

因此，可以将关联较强的一组特征同时 Mask。通过互信息（Mutual Information，MI）衡量不同特征之间的统计关联程度：

$$
MI(U,V)=
\sum_u\sum_v p(u,v)\log\frac{p(u,v)}{p(u)p(v)}
$$

其中 $p(u)$ 为某特征取值为 u 的概率。

具体流程：

1. 假设共有 $k$ 种特征，离线计算特征两两之间的互信息，得到 $k\times k$ 的关联矩阵。
2. 随机选择一个特征作为种子。
3. 找到与种子最相关的 $\frac{k}{2}$ （具体数量可根据实现调整）种特征。
4. 同时 Mask 种子及其相关特征，保留其余特征。

假设离线计算发现，“关键词”和“品牌”与“类目”的关联较强。以“类目”为种子，同时遮盖这三个字段：

| 特征字段 | 原始物品 | 变换后 |
|---|---|---|
| 物品 ID | V1001 | V1001 |
| 类目 | 数码、摄影 | **default** |
| 关键词 | 佳能、相机、摄影教程 | **default** |
| 城市 | 上海 | 上海 |
| 品牌 | 佳能 | **default** |
| 价格 | 5000～10000 元 | 不变 |


下面总结一下自监督学习流程：

从全体物品中均匀随机采样 $m$ 个物品，组成一个 batch：

$$
B=\{b_1,b_2,\ldots,b_m\}
$$

对每个物品进行两次独立的随机特征变换，并通过共享的物品塔生成两组向量：

$$
B'=\{\mathbf b_1',\mathbf b_2',\ldots,\mathbf b_m'\}
$$

$$
B''=\{\mathbf b_1'',\mathbf b_2'',\ldots,\mathbf b_m''\}
$$

其中，$\mathbf b_i'$ 和 $\mathbf b_i''$ 来自同一个物品的不同特征视图。

接下来以 batch 中第 $i$ 个物品为例，计算单个物品的损失。固定第一组中的向量 $\mathbf b_i'$，将其作为锚点 Anchor，分别与第二组中的全部 $m$ 个向量计算余弦相似度：

$$
\cos(\mathbf b_i',\mathbf b_1''),\,
\cos(\mathbf b_i',\mathbf b_2''),\,
\ldots,\,
\cos(\mathbf b_i',\mathbf b_m'')
$$

其中：

- **正样本**：$(\mathbf b_i',\mathbf b_i'')$，来自同一个物品。
- **负样本**：$(\mathbf b_i',\mathbf b_j'')$，其中 $j\ne i$，来自不同物品。

因此，对于第 $i$ 个物品，我们构造了一个包含 1 个正样本和 $m-1$ 个负样本的分类问题。

然后通过 Softmax 将相似度转换为概率：

$$
s_{i,j}
=
\frac{
\exp(\cos(\mathbf b_i',\mathbf b_j''))
}{
\sum_{k=1}^{m}
\exp(\cos(\mathbf b_i',\mathbf b_k''))
}
$$
这可以看作一个 Listwise 形式的多分类问题，因此，第 $i$ 个物品的交叉熵损失为：

$$
L_{\text{self}}[i]=-\log s_{i,i}
$$

![](\images\王树森推荐系统\img28.png)

虽然第 $i$ 个物品只有一个损失值，但这个损失是通过它与全部 $m$ 个候选向量的相似度共同计算出来的。现在只计算了第 $i$ 个物品的损失。但一个 batch 中共有 $m$ 个物品，**每个物品都会轮流作为 Anchor，构造一个候选匹配问题**。

因此：

| Anchor | 正样本 | 负样本 | 对应损失 |
|---|---|---|---|
| $\mathbf b_1'$ | $\mathbf b_1''$ | 其余 $m-1$ 个 | $L_{\text{self}}[1]$ |
| $\mathbf b_2'$ | $\mathbf b_2''$ | 其余 $m-1$ 个 | $L_{\text{self}}[2]$ |
| $\vdots$ | $\vdots$ | $\vdots$ | $\vdots$ |
| $\mathbf b_m'$ | $\mathbf b_m''$ | 其余 $m-1$ 个 | $L_{\text{self}}[m]$ |

也就是说：一个物品作为 Anchor，产生一个交叉熵损失。而一个 batch 有 $m$ 个 Anchor，因此产生 $m$ 个交叉熵损失。将这 $m$ 个损失求平均，得到整个 batch 的自监督损失。

$$
\mathcal L_{\text{self}}
=
\frac{1}{m}
\sum_{i=1}^{m}L_{\text{self}}[i]
$$

实际训练时，通常将双塔主任务与物品自监督任务结合，两个任务分别计算平均损失，再进行加权求和。

对于双塔模型，采用 batch 内负样本 + listwise 训练方式，从用户点击数据中随机采样 $n$ 对用户—物品正样本，组成一个 batch。对于第 $i$ 个用户，构造了一个包含 1 个正样本和 $n-1$ 个负样本的候选匹配问题。因此，第 $i$ 个用户的交叉熵损失为：

$$
L_{\text{main}}[i]=-\log s_{i,i}
$$
一个 batch 有 $n$ 个用户—物品正样本对，因此产生 $n$ 个交叉熵损失。将这 $n$ 个损失求平均，得到整个 batch 的主任务损失:

$$
\mathcal L_{\text{main}}
=
\frac{1}{n}
\sum_{i=1}^{n}L_{\text{main}}[i]
$$

**注意，主任务 batch size $n$ 与自监督任务 batch size $m$ 可以不同。**

最后，将两个任务的平均损失加权求和：

$$
\mathcal L_{\text{total}}
=
\underbrace{
\frac{1}{n}\sum_{i=1}^{n}L_{\text{main}}[i]
}_{\text{双塔主任务平均损失}}
+
\alpha
\underbrace{
\frac{1}{m}\sum_{j=1}^{m}L_{\text{self}}[j]
}_{\text{物品自监督平均损失}}
$$

#### 曝光过滤 & Bloom Filter

曝光过滤是指：如果用户已经看过某个物品，就不再将该物品推荐给用户。

推荐系统需要记录每个用户历史曝光过的物品。在召回阶段结束后，判断召回的候选物品是否已经曝光，并过滤掉已曝光的物品，再将剩余物品送入排序阶段。

例如，小红书只召回近一个月发布的笔记，因此只需要维护相应时间范围内的曝光记录。

如果直接遍历用户的历史曝光物品进行判断，计算开销较大。因此，可以使用 Bloom Filter（布隆过滤器），通过较小的存储空间快速判断物品是否属于已曝光集合。

Bloom Filter 使用一个长度为 $m$ 的二进制数组表示物品集合：

$$
V=[0,0,\ldots,0]
$$

其中：

- 每个用户维护一个 Bloom Filter，存储空间为 $m$ bit。
- 初始时，数组中的所有位置均为 0。
- Bloom Filter 使用 $k$ 个哈希函数，每个函数将物品 ID 映射到 $[0,m-1]$ 的整数位置。

举一个具体的例子，假设二进制数组的长度 $m=10$，哈希函数数量 $k=3$，用户已经曝光物品 ID 为 101。那么首先将物品 ID 写入三个哈希函数：$h_1(0)=2, h_2(0)=5, h_3(0)=8$，然后将三个哈希函数得到的结果对应到二进制数组中，将数组中第 2、5、8 号位置设置为 1。

![](\images\王树森推荐系统\img29.png)

后续如果曝光了其他物品，也重复这个过程：计算 $k$ 个哈希位置，将对应位置置为 1。如果某个位置已经是 1，则保持不变。

反之，当我们查询召回物品是否被曝光时，对于召回物品 $b_j$，同样计算 $k$ 个哈希位置，并检查对应位置的值：若全部为 1，那么该物品可能已经曝光。若至少有一个位置为 0，那么该物品一定没有曝光。这是因为不同物品经过哈希函数后，可能映射到相同的位置，产生哈希碰撞。

因此，Bloom Filter 存在两种判断特点：

- 可能出现假阳性（False Positive）：物品实际上没有曝光，却被误判为已曝光。
- 不会出现假阴性（False Negative）：在已曝光物品成功写入且没有错误删除的前提下，不会将其判断为未曝光。

![](\images\王树森推荐系统\img30.png)

需要注意，哈希函数数量 $k$ 并不是越多越好。增加哈希函数可以在一定范围内降低误判率，但过多的哈希函数会导致数组中更多位置被设置为 1，反而增加误判率。

曝光过滤的具体流程：曝光过滤可以分为**曝光记录写入**和**召回结果过滤**两个过程。

1）曝光记录写入

```text
用户浏览物品
     ↓
产生曝光事件
     ↓
Kafka 接收曝光数据
     ↓
Flink 实时处理曝光记录
     ↓
计算物品 ID 的哈希值
     ↓
更新该用户的 Bloom Filter
```

曝光记录需要尽可能实时更新，否则用户快速刷新时，可能再次看到已经曝光过的物品。

（2）召回结果过滤

```text
召回服务器得到候选物品
          ↓
请求曝光过滤服务
          ↓
获取用户的 Bloom Filter
          ↓
计算候选物品的 k 个哈希位置
          ↓
检查对应的二进制数组
          ↓
过滤可能已曝光的物品
          ↓
剩余候选物品进入排序阶段
```

![](\images\王树森推荐系统\img31.png)

Bloom Filter 还有一个缺点，只支持插入和查询，但不支持直接删除物品。Bloom Filter 插入物品时，只需要将对应的 $k$ 个位置设置为 1；但删除物品时，不能直接将这些位置设置为 0。因为不同物品可能通过哈希函数映射到同一个位置。

例如：

$$
A\rightarrow{2,5,8}
$$

$$
B\rightarrow{3,5,9}
$$

物品 A 和 B 都使用了第 5 号位置。

如果删除 A 时，将位置 2、5、8 全部设置为 0，那么 B 对应的第 5 号位置也会被清零，导致查询 B 时错误地认为它不存在。所以，Bloom Filter 只支持添加物品，不支持删除物品。

因为 Bloom Filter 这一不足，随着曝光物品的增加，数组中越来越多的位置被设置为 1，导致未曝光物品也更容易被误判为已曝光。所以需要每天（定期）重构 Bloom Filter，十分麻烦。
